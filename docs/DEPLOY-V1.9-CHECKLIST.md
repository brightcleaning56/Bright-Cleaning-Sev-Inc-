# Deploy checklist: BUILDINTEL on Render

## Which repo Render builds from
- **Repo:** `brightcleaning56/buildintel`
- **Branch:** `claude/buildintel-launch-requirements-i9bmnu`
- **Blueprint:** `render.yaml` (service `buildintel`, Postgres `buildintel-db`)
- `brightcleaning56/Bright-Cleaning-Sev-Inc-` (same branch) is a mirror of this code. Make changes in `buildintel`, then copy them to the mirror.
- If the service builds from any other repo or branch, change it in Render → service → Settings to the repo and branch above.

## Values to set on the service (marked `sync: false` in render.yaml)
- `OWNER_EMAIL`: the platform owner's sign-in email.
- `OWNER_PASSWORD`: at least 12 characters. Store it in a password manager.
- `BACKUP_KEY`: 64 hex characters (32 bytes), used to encrypt backups. Keep a copy; backups cannot be restored without it.
- `BASE_URL`: the public address of the service, for example `https://<service-name>.onrender.com`. Confirmation and unsubscribe links are built from it, so it must be correct.
- `SAM_API_KEY`: only if the SAM.gov source is enabled.
- `APP_SECRET` is generated by Render. Do not change it after launch; sessions and links are signed with it.

## Steps
1. Confirm the repo and branch above in Render → service → Settings.
2. Set the values above, then **Manual Deploy → Clear build cache & deploy**.
3. Wait for the deploy to finish, then check `https://<BASE_URL>/health` returns `{"ok":true,...}` with `"storage":"postgres"`.
4. Open `/` (website), `/get-started`, `/app` (sign in as the platform owner) and `/admin`.
5. Keep `EMAIL_MODE=dry-run` until the email provider is configured and verified. Then change it in render.yaml and in the service.

## What the build does
- `npm ci` installs dependencies. Tests are not run during the Render build; they run in CI (`npm run test:ci`) and before release.
- Start command: `node src/server.js`. Node 22 (`NODE_VERSION`).

## Not included in this deploy
- Live payments, live email sending and live data sources need their own setup and approval. See `docs/LAUNCH_24H.md`.
